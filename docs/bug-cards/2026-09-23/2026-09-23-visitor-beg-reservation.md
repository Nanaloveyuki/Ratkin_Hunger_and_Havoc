# 访客批量乞讨目标竞争导致 Pawn 卡住

| 字段 | 内容 |
| --- | --- |
| 复现 | 0.1.0 新游戏，开发者事件页触发 I-001 大批访客；观察多个访客进入乞讨或等待，并检查 Player.log |
| 期望 / 实际 | 期望每个 Beg Job 只选择当前可预订且可达的殖民者，目标竞争时访客重新选择其它行为或等待；实际多个 Pawn 同时选择同一殖民者，JobDriver 预订失败并连续输出 `Could not reserve` / `TryMakePreToilReservations returned false`，部分 Pawn 静止在等待中 |
| 版本 | 0.1.0 |
| 级别 | S1 |
| 根因 | `JobGiver_RHAH_Beg.FindClosestColonist` 只检查可达，不检查目标预订状态；同一 Tick 内多个访客生成相同目标，JobDriver 启动时才竞争预订。无食物兜底还可能把 Pawn 固定到无效等待点 |
| 最小修复 | 候选殖民者筛选使用非报错预订检查；Beg Driver 处理同帧预订竞争时静默失败；WaitFood 只创建有效站立等待点并保留既有重试节流 |
| 明确不做 | 不改变乞讨成功结算、殖民者态度、访客人数、赈灾区规则、存档键、API、事件目录或其它 Job 的目标选择 |
| Language | 无 |
| 存档 | 无 |
| 归属表 | 否 |
| 回归 | 规则测试覆盖已占用目标不可选；源码契约覆盖候选预订过滤和 Driver 非报错失败；定向测试、构建和结构检查通过 |
| 后续债 | 若真实游戏中仍有等待中的 Pawn，继续采集其具体 Job、Duty 和目标位置；本次不重写整个寻食闭环 |
