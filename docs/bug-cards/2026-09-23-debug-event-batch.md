# 手动开发者事件多人批次永久排队

| 字段 | 内容 |
| --- | --- |
| 复现 | 0.1.0 新游戏。在 IrisMenus 开发者事件页手动触发 I-002、I-001 或其它多人地图事件，关闭窗口后观察 Player.log 与事件页状态 |
| 期望 / 实际 | 期望窗口关闭后的下一帧完成整批生成并从队列移除。实际第一只 Pawn 生成后登记批次，第二只 Pawn 命中 `DuplicateBatch`，整批回滚，Worker 返回 false，队列永久保留并反复重试 |
| 版本 | 0.1.0 |
| 级别 | S1 |
| 根因 | `RHAH_PawnFactory.Create` 在单个 Pawn 成功时登记 `Map + SpawnBatchId`，而 `RHAH_IncidentFacts.Submit` 用同一批次 ID 循环创建多人事件。第二次创建把同一逻辑批次错误当成重复事件 |
| 最小修复 | 多人事件创建期间延迟批次登记；整批全部创建成功后由 `RHAH_IncidentFacts` 登记一次。保留工厂对已有活动批次的重复保护 |
| 明确不做 | 不改窗口暂停生命周期、不改变队列失败保留策略、不改事件点数、Def、API、存档键或其它单人/商队生成路径 |
| Language | 无 |
| 存档 | 无新键；仅调整运行时批次登记时机 |
| 归属表 | 否 |
| 回归 | 覆盖多人事件批次必须在整批成功后提交；验证 I-002/I-001 关闭 IrisMenus 后生成并清除队列，日志不再重复 `did not spawn` |
| 后续债 | 若 Worker 因真实地图无入口格或 Pawn 生成资源缺失返回 false，仍需通过日志定位具体环境条件；本次不把真实失败强制当成功 |
