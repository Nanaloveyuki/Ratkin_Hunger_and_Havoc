# 来客食物交接偶发失败或继续离场

| 字段 | 内容 |
| --- | --- |
| 复现 | 玩家报告偶发、无日志且无法稳定复现。代码可构造：来客进入离场 toil 后点击投喂；来客已有赶路任务时切入等待投喂；同批两人等待，其中一人等待期限先到 |
| 期望 / 实际 | 只有实际进入可交接等待的来客才接受投喂，等待时停下原赶路，单人的截止不取消其它人的交接 / `Start` 在离场 toil 仍返回成功却没有进入原版 `IWaitForItemsLordToil`，投递随后静默失败；转等待不结束现有赶路；任一接收者到期会使整批退出等待 |
| 版本 | 1.0.5 开发版 |
| 级别 | S2 |
| 根因 | `RHAH_FoodHandoff.Start` 把登记接收者当作交接成功，未核对当前 Lord toil 与 Leaving 生命周期。等待转换只改 duty、不结束旧 Job；`FoodWaitExpired()` 按任一成员到期结束整批等待，且结束后留下旧接收名单和食物类型 |
| 最小修复 | 投喂入口重查资格，拒绝已离场状态并核对实际等待 toil；切入等待中止原任务；仅所有未收齐的接收者都到期才结束等待，到期成员独立转离场 duty，退出后清当轮名单与食物类型 |
| 明确不做 | 不声称覆盖玩家所有无复现症状，不加日志轮询、重试或延长期限，不阻止正常到期、驱逐、敌对或商队环境离场，不改原版搬运驱动，不接管袭击或拦截 Lord |
| Language | 无，沿用现有拒绝提示 |
| 存档 | 无，沿用现有接收名单、食物类型和每人截止键 |
| 归属表 | 否 |
| 回归 | 真实 Lord 图测试覆盖离场拒绝且无登记副作用、赶路转等待后原版识别可交接、错开截止仍保留未到期成员、收齐成员不触发他人超时、退出清当轮名单与下一轮重新登记 |
| 玩家复测 | 在原出问题的存档中向仍在赶路的来客投喂，观察停下、交接和后续进食；同批错开时间投喂两人，确认一人到期不取消另一人的交接；已进入离场状态的来客应拒绝投喂 |
| 后续债 | 原玩家场景未稳定复现，不能断言所有症状同根因；游戏窗口内完整搬运、寻路与其它模组干预需手工观察 |
