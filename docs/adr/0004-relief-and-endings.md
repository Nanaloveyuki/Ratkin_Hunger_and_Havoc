# ADR 0004: 救济成败与结局

## Context

结局只有一条优先级，却吃两个互不回写的计数。`aidCount` 在点下交付时加一。`completedKindCount` 数的是穗音经历里成功关掉的种类。玩家看到的信写「安全离开或持续安置才算一次」，账上记的是「点了交付」。

经历打开时 `Delivered` 固定为 false，之后没有人再改。因此「交出物资后安全离开」几乎永远不算成功，低结局几乎只剩全员安置。

五个结局现在可以在非穗音叙事者下触发，也可以在同一档里先后出现。`endingE01` 到 `endingE05` 是五条独立标记，没有「这一档已经结束」的总闸。

信任和剧情节点已经在 IrisMenus 叙事页。旧项目把信任和正在追踪的事件放进警报栏，追踪会异常。本仓库不建警报栏追踪。

1.0.0 前允许重建实验性存档语义。旧 `aidCount` 是交付次数，不能当成新规则下的成功批次数。

## Decision

### 玩家须知

只有穗音在记的时候，这些批次才算进结局。其它叙事者不记，也不出结局。

要物资的一批，物资交出去之后才开始算。不要物资、已经答应留下的一批，从答应时开始算。只换地点的情报不算救济。

还活着的人后来都安全离开，或在原地入籍、吃饱、没病地住满五天，这一批才算成功。成功在这一批结束时记一次。

冻死、热死、饿死、病死、被别人或动物杀死、老死，不扣信任，也不让这一批失败。人已经死了，就不再参加成败判定。

玩家用枪、近战、陷阱或其它己方暴力杀死其中任何一人，这一批立刻失败。信任 −10，每批只扣一次，不按人数累加。这一批里其余人以后安顿好，也不补记成功。整批转成敌对是他们自己的态度，不再另扣信任。

人没死，并且已经不在原来那张地图上，算安全离开。不要求走到地图边缘。关进监狱或奴役不算离开，也不能因此算成功。

拒绝、一天超时、忽视、俘虏、奴役、攻击、投喂、主动驱逐都不算成功。主动驱逐仍单独计数，次数超过上限就挡高结局。

结局每档只出一次，写进存档。丰年条件先满足就发丰年，希望之城以后人数够了也不再发。关掉的那一条跳过，不会改去触发另一条。

### 一批怎么关

记救济的批次沿用经历 14。打开时仍不把 `Delivered` 写成 true。玩家交付物资，或接受一项没有物资索取的承诺时，才把这一批标成已答应。

没有物资索取、接受即承诺的是：遗弃 `I-002`、`I-003`、`I-037`，逃难者 `I-011`，空投 `I-032`、`I-046`，认亲 `I-033`、`I-047`。鼠疫变体里走同一条承诺的 `I-040`、`I-042` 同样从接受时开始算。

要物资的是接济 `I-015` 到 `I-019`，以及易子而食 `I-013`。库存不足不算答应。

成败只看仍活着的人。

- 玩家直接杀死任何一人：立刻失败。失败后不再观察，永不记成功。
- 活着的人全部安全离开，或在原地图以玩家派系、不饿不病地安置满五天，并且这一批已经答应：关闭并记一次成功。全员安置时，即使没有单独的物资交付，也算已经答应。
- 活着的人里还有人悬着：继续观察，最多三十天。到期仍有活人未离开也未安置满五天：关闭，不计成功。
- 没有活人，且没有人是被玩家直接杀死的：立刻关闭，不计成功，也不标失败。叙事页写「这一批已结束，无人存活，不计救济」。信任不变。
- 被驱赶、拒绝、超时、俘虏、奴役：关闭，不计成功。

同一批只记一次。成功批次数就是 `aidCount`。低结局继续用其中出现过的种类数，不另计次数，也不用完成比率。

非玩家直接杀死包括冻死、热死、饿死、病死、老死，以及友军、动物、其它派系或自然原因。已经死亡的人再被补刀，不算玩家杀死。

玩家直接杀死沿用现有外部暴力判定：伤害来自玩家派系，且对该 pawn 构成外部暴力。殖民者的枪、近战和陷阱都在内。

### 结局

`RHAH_EndingRules.Next` 先要求当前叙事者是 `RHAH_Suiyin`。非穗音不累计 `aidCount`、广播、驱逐和完成种类，也不触发 `E-01` 到 `E-05`。

删除「非穗音也计数」和「非穗音也出结局」。结局页不再提供这两个开关。

五个结局仍是 `E-01` 鼠族丰年、`E-02` 希望之城、`E-03` 没有答案的记录、`E-04`、`E-05`。优先级不变：先看高结局，再看信任跌破，再看低结局。

高结局门槛不变：成功批次达到接济门槛，广播达到门槛，主动驱逐不超过上限。希望之城额外要求成年饥荒鼠族人数和信任至少 75。丰年额外要求信任至少 50。两者同时可发时仍先发希望之城。只有丰年可发时立刻发丰年，并占掉这一档。

低结局仍要至少六种成功经历，并等满设置里的天数。信任降到 −75 及以下走 `E-05`，它先于低结局。

每档只落一个。存档沿用 `endingE01`、`endingE02`、`endingE03`、`endingE04`、`endingE05`。其中一条为 true 就是这一档的结局，读档后不再触发第二条。不新增 `triggeredEnding`。玩家关掉某一条时，那一条跳过；不会因为关掉它而改发一条当前条件不成立的结局。

`R-01` 身份询问不是结局，不占这一个名额。

### 信任与追踪

信任和 `N-001` 到 `N-010` 的开关、进度只出现在 IrisMenus 叙事页。不注册警报，不用警报栏显示信任或正在追踪的事件。

玩家直接杀死的信任变化是每批 −10，只记一次。俘虏仍是 −5。态度变敌对不改信任。

### 旧档

`aidCount` 的语义改为成功批次数。1.0.0 前不迁移旧值。读到旧档时这个数作废，从 0 按新规则重计。修复实现时把这一点写进修复卡和 `docs/save-ownership.md`。

## Consequences

- 交付只给批次打上已答应，不增加 `aidCount`。
- 高结局从「点了 99 次交出」变成「99 批活人被送走或安置」。门槛数值不变，达成更晚。
- 全员非玩家死亡的批次不挂满三十天。
- 非穗音存档不再出现这五个结局，结局页少两个开关。
- 已触发任一 `endingE0x` 的存档不会再出第二个结局。
- 后续实现须改 `CloseJournal`、交付路径、`Counts`、`Next` 和结局页。本 ADR 不改基因、经历条目和特质。
