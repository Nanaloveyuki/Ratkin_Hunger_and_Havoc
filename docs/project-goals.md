# 项目目标与实现路线

## 1. 项目定位

本项目是《鼠族: 饥与祸》的独立重写版本。旧项目只作为玩法规格和行为对照，不复制旧源码、旧存档格式或旧内部命名。

目标不是一次性恢复全部旧内容，而是先建立可验证的核心模型，再按事件、叙事和角色行为逐批迁移。所有新实现必须服从 [engineering.md](engineering.md)、[pawn.md](pawn.md)、[incidents.md](incidents.md)、[bug-handling.md](bug-handling.md) 和已接受 ADR。

### 总目标

- 保留旧项目的核心玩法面：饥荒事件、鼠疫事件、访客行为、救济互动、穗音叙事和结局
- 用来源标记、角色和生命周期替代经历猜测与空标签 Hediff
- 用独立 API 提供跨模组查询、行为覆盖和事件通知
- 在不依赖其它模组私有实现的前提下兼容 Ratkin 框架、牵宠物、幼儿、囚犯和 UI 类模组
- 将事件目录、存档字段、API 签名和命名规则变成可自动检查的契约

## 2. 优先级与范围

### P0：重写基础，不恢复旧功能

这是所有玩法实现的前置条件。

- 拆分 `HungerAndHavoc.Api.dll` 与实现程序集，API 不引用 Verse、实现类型或 `CompHungerPawn`
- 按工程标准修正命名空间、访问级别、文件路径和反射入口例外
- 完成 `IHungerPawn` 只读快照，事件参数不得暴露 Hediff、Comp、Job 或 Worker
- 固化 `CompHungerPawn` 的存档键、默认值、空集合语义和生命周期转换
- 将 `HungerRace.Register` 等内部入口收敛为稳定 API 的鼠族匹配注册
- 建立 API 白名单、Def/Keyed/workerClass、存档契约和旧命名禁用检查
- 保持 Guard、旧包冲突检测和独立 packageId 的边界

P0 未完成前，不新增依赖 API 的外部兼容代码，不把实验性实现作为公开契约。

### P1：旧项目核心玩法重写

- 事件生成和访客生成管线
- Pawn 来源、角色、关系组、生命周期和离场
- 乞讨、偷窃、战斗、进食、啃咬、携带、牵引、加入和囚禁等行为闸门
- 救济、鼠疫和商队事件
- 事件调度、随机权重、设置开关和调试触发

P1 的目标是形成“事件可以完整生成、Pawn 可以完成生命周期、玩家可以处理后果”的最小可玩闭环。

### P2：叙事与内容完整度

- `N-001`~`N-010` 剧情节拍
- `J-001`~`J-014` 记录
- `R-01` 揭示
- `E-01`~`E-05` 结局
- `H-Axxx` / `H-Yxxx` 经历和 `T-xxx` 特质
- 中文、英文本地化和缺失键检查

### P3：兼容与打磨

- 外部模组 API 示例和兼容测试
- 高负载地图、多人 Pawn、存档重载和事件重复触发测试
- 调试入口、错误日志、玩家可见提示和设置项
- 发布包、构建脚本、Guard 和版本目录验证

## 3. 领域目标

### 3.1 事件

事件目录以 `I-001`~`I-051` 为稳定显示 ID，Def 使用可读的 `RHAH_` 名称。显示 ID 是数据契约，不是列表下标。

实现要求：

- 先实现通用生成上下文、批次 ID、关系组和 `HungerPawnSeed`
- 同类事件共用生成和 Worker 逻辑，鼠疫通过参数或策略注入，不复制近似 Worker
- 每个事件明确 Family、Origin、Category、Target、态度池和调试点数
- 事件必须能安全处理目标地图、商队、无可用 Pawn、人口上限和重复触发
- 目录项可以先存在而未实现，但未实现项不得伪装成可触发内容
- 每个完成事件都要有 Def、Worker、关键本地化键、生成测试和至少一次游戏内验证

实现顺序：

1. `I-001`~`I-014` 原作基础事件
2. `I-015`~`I-035` 救济、情报、商队和特殊事件
3. `I-036`~`I-051` 鼠疫和高风险事件

### 3.2 结局与叙事

叙事状态必须与事件状态分离。事件号不得占用 `N-`，结局不得依赖某个 Pawn 是否仍在地图上。

- 以持久化叙事状态记录关键选择、救济结果、信任、损失和揭示进度
- 结局判定使用明确的状态快照和优先级，避免多个结局同时触发
- 结局计算必须可重复、可调试、可在存档重载后继续
- 结局展示与事件 Worker 解耦；事件只提交事实，不直接决定最终结局
- 旧项目中的隐式全局变量、事件号推断和文本匹配必须改为命名字段

### 3.3 Pawn 逻辑

Pawn 的身份分为种族、来源、访客、角色、经历和有效状态。经历只负责技能与文本，不参与来源或访客判定。

- `RHAH_HungerMark` + `CompHungerPawn` 保存来源和运行时状态
- 角色决定默认行为，生命周期决定当前阶段，闸门决定可否执行具体行为
- 招募、囚禁、奴役或加入玩家派系时统一调用 `ReleaseToColony`
- 死亡、地图转移、跨地图和存档重载必须保持来源数据一致
- 任何行为实现都不得重复角色判定；统一调用 API 的闸门查询
- 访客逻辑在高频路径避免 LINQ、临时集合和重复 Def 查询

生命周期验收：

`Arriving -> SeekingFood -> Fed -> Leaving -> Released | Dead`

每次转换必须定义触发条件、允许的前置状态、存档结果和对外事件顺序。

### 3.4 对外 API

API 是长期兼容边界，优先稳定、少量、可验证。

首期公开范围：

- `HungerAndHavocApi`
- `IHungerPawn`
- `HungerPawnSeed`
- `HungerPawnRole`、`HungerLifecycle`、`HungerReleaseReason`、`HungerAttitude`
- `HungerBehaviorGate`
- `HungerPawnBehaviors`
- `IHungerPawnBehavior`

规则：

- 查询返回只读快照或基础类型
- 修改只经 API 方法完成
- API 事件参数使用稳定快照和基础游戏类型
- 事件顺序、闸门优先级、注册顺序和 null 语义必须写测试
- 新增公开成员先更新文档和 ADR，再实现
- API 不承诺旧项目类型名、旧存档字段或私有 Harmony 路径

### 3.5 对外 Mod 兼容

兼容优先使用 API 和 Def 扩展，Harmony 只补原版或种族框架缺口。

- Ratkin 判定允许注册匹配器，但不要求外部模组扫描本模组 Hediff
- 外部模组可查询来源、访客、角色和生命周期
- 外部模组可通过单 Pawn 闸门、行为策略和事件订阅改变行为
- `extraData` 使用 `packageId:key` 命名，所有权归写入方
- 兼容目标模组必须登记加载顺序、可选依赖、失败策略和测试范围
- 不针对其它模组私有 Job、Comp、字段或反射路径打补丁
- 旧鼠灾包冲突由 Guard 提示并阻止主体加载，不进行自动停用或存档转换

首批兼容验证对象：Ratkin 种族框架、Lead Your Pets、Toddlers、囚犯/奴隶扩展和 IrisMenus。没有稳定 API 需求的模组不增加专用适配层。

### 3.6 特质与角色经历

特质和经历是内容，不是身份系统。

- `H-Axxx` 表示成年经历，`H-Yxxx` 表示幼年经历，`T-xxx` 表示本模组特质
- 每条经历明确技能、标签、年龄条件、兼容性和本地化键
- 特质必须提供实际可观察效果；只有文本标签的内容不进入正式发布
- 角色默认行为不得通过经历名称、标签或文本判断
- 生成器只根据事件角色和年龄条件选择内容，生成后不反向改变来源身份
- 旧项目的经历和特质先建立清单，再逐条重写；无法解释的旧效果标为待决策，不直接复制

## 4. Bug 处理与质量门禁

流程、修复卡、Language / 存档 / 卸载门禁见 [bug-handling.md](bug-handling.md)。存档键和归属表见 [save-ownership.md](save-ownership.md)。

### 缺陷分类

- **S0**：崩溃、存档损坏、API 破坏、旧包冲突失效，立即阻断发布
- **S1**：核心生命周期卡死、事件无法完成、Pawn 行为失控、结局错误
- **S2**：单个事件、翻译、UI 或兼容策略错误，有明确绕过方案
- **S3**：平衡、文本、调试体验和性能建议

### 发布阻断

发布前必须通过 [engineering.md](engineering.md) 的检查门禁，以及至少一次新游戏、存档重载、事件完成和结局流程验证。Language、存档键登记和卸载归属的自动检查尚未完全落地时，按文档人工核对，不能因为脚本缺失而跳过。

## 5. 里程碑与完成定义

### M0：契约基线

API 与实现程序集边界正确，Pawn 快照和存档契约稳定，检查门禁可运行。

### M1：最小可玩闭环

至少完成一条原作求助事件和一条敌对事件，包含 Pawn 生成、行为、救济/冲突、离场和存档重载。

### M2：原作事件重写完成

`I-001`~`I-014` 全部可触发、可完成或明确失败，行为不依赖旧项目源码。

### M3：续作内容重写完成

`I-015`~`I-051`、鼠疫、商队和特殊分支按目录实现，重复逻辑已抽取到明确领域组件。

### M4：叙事与角色内容完成

剧情、记录、揭示、结局、经历和特质具备完整本地化、测试和调试入口。

### M5：发布候选

所有阻断级检查通过，兼容对象完成验证，已知 S0/S1 为零，发布包可独立安装。

一个里程碑只有在其验收项和回归测试完成后才算完成；“目录已登记”不等于“功能已实现”。

## 6. 当前进度

M0 到 M3 已落地：API 与 Identity、原作 `I-001`..`I-014`、续作 `I-015`..`I-051` 的目录和 IncidentDef、生成管线、访客运行时、`GameComponent` / `MapComponent`、IrisMenus 只读与设置页面。

未完成，不能写成已实现：

2. 结局开关、生物科技基因设置、经历生成概率、事件频率函数。IrisMenus 对应页面只显示不可用
3. M5：真实游戏的新开局、存档重载、事件完成和发布包验收

目录已登记不等于玩法已完成。不要为了补页面去伪造这些缺口的数据。
